# RK3326 掌机：首版产品基线、交互与验收用例

版本：V0.1；日期：2026-10-29；状态：可用于立项与样机验收的执行稿，尚未实机验证。承接[产品需求书](01_PRODUCT_REQUIREMENTS.zh-CN.md)，本文件把产品描述转换为研发可领任务、测试可判定的条目。建议指标必须在 G0 评审签定后才成为合同或宣传规格。

2026-10-29 更新：RK3326 仅保留为参考样机基线，新产品不再锁定该芯片；候选主平台按[11 替换方案](11_RK3326_REPLACEMENT_STRATEGY.zh-CN.md)重新冻结。国内外需求以本文第 9 节及[10 手册第 13 节](10_PROJECT_PROCUREMENT_PILOT_EXECUTION.zh-CN.md#13-国内与海外销售的新增工作包2026-10-29)为增量，取代此前“销售地区待定即可继续冻结”的假设。

## 1. 首版到底交付什么

交付一台采用通过供货和维护评审的新主平台、实体按键和双摇杆、离线运行游戏前端与选定模拟器的竖式掌机，同时交付对应硬件版本的恢复镜像、用户说明和售后诊断办法。优先评估 Linux 成熟板卡整合版；Android 属另行评审路线。新主板按[硬件执行方案](08_ELECTRONICS_SCHEMATIC_BRINGUP.zh-CN.md)单独推进。

| 项目 | 首版基线 | 冻结需要的证据 |
| --- | --- | --- |
| 显示 | 640×480、4:3，约 3.5 英寸候选；一个稳定显示模式 | 屏完整料号、规格书、时序、实测照片与测量记录 |
| 输入 | 十字键、ABXY、L1/R1/L2/R2、双摇杆、FN/SELECT/START、音量和电源 | 逐键事件表、四轴校准、组合键与装壳测试 |
| 存储 | 首版优先双 microSD：系统卡和内容卡 | 实际挂载路径、文件系统、容量、插拔策略和恢复报告 |
| 音频 | 内置扬声器和 3.5 mm 耳机输出 | 输出切换、噪声、音量、静音与负载确认 |
| 供电 | 单节锂电包、USB-C 5 V 输入设计方向 | 电芯与保护规格、端口角色、充电和温升测试 |
| 系统 | 实体键进入菜单、选择内容、运行、存档、退出和安全关机 | 完整流程录像、版本清单和存档重启校验 |
| 首发平台 | 第一轮验证 GB/GBC/GBA、FC/NES、SFC/SNES、MD；具体核心另审 | 每个平台有核心版本、测试内容、性能与许可记录 |
| 扩展平台 | PS1、PSP、N64、Dreamcast、街机按具体作品评估 | 不以“菜单有图标”作支持证据，不承诺全库满速 |
| 内容 | 自有或明确获授权的演示内容；允许用户导入内容 | 内容清单、来源、权利范围和对应模拟器版本 |

不把 Wi-Fi、蓝牙、HDMI、触屏、USB-PD 快充和联网商店加入首版固定范围；新增其中任一项都应重新评估原理图、结构、固件和验证工作量。

## 2. G0 必须决定的商业与产品边界

| 决策 ID | 需要填定的内容 | 默认推进假设 | 决策责任与截止 |

| DEC-01 | 国内与首个海外目标国家/地区、渠道、年龄定位及责任主体 | 离线个人游玩；市场未选定前仅作原型研究，不作该市场量产冻结 | 产品负责人，G0 前 |
| DEC-02 | 含税售价、单台成本上限、研发和模具预算 | 先询价，不以网络零售价代替 BOM 报价 | 产品与采购，G0 |
| DEC-03 | 首批数量、颜色、包装、附件 | 一个硬件组合、一个颜色，减少变量 | 产品与制造，G0 |
| DEC-04 | 供应商板卡整合或自研主板 | 优先成熟板卡；必须可追溯和取得维护资料 | 硬件与项目，G0 |
| DEC-05 | 系统和内容卡容量、是否附充电器 | 容量按镜像和获授权内容测算 | 产品与软件，G0 |
| DEC-06 | 续航、重量、外形和开机时间指标 | 采用第 5 节候选值，先测样机再冻结 | 产品与测试，G0 |
| DEC-07 | 首发核心、演示游戏、素材、品牌 | 少量可维护核心和可授权演示 | 软件与内容负责人，EVT 前 |
| DEC-08 | 售后期限、维修方式、固件维护周期 | 必须有负责人和成本预算，期限待定 | 产品与售后，DVT 前 |

预算、数量尚缺时可以测绘、建基线和询价；不能由执行人员自行把空白项填写成客户承诺。

## 3. 用户界面与操作合同

| 页面/状态 | 必须显示和允许的操作 | 异常处理 |
| --- | --- | --- |
| 首次开机 | 语言、确认/返回键提示、演示内容入口 | 无内容卡仍能进入系统设置与关机 |
| 平台首页 | 有效平台、内容数量、最近游玩、收藏、设置 | 不支持平台隐藏；不能用文件数量冒充可运行数量 |
| 游戏列表 | 标题、收藏、启动、刷新；封面允许缺失 | 损坏封面不阻断列表；中文名不乱码 |
| 游戏运行中 | 音量/亮度反馈、热键说明、保存/退出 | 进程失败回到前端并留下错误编号 |
| 存档管理 | 原生存档与即时存档分开说明、保存反馈 | 空槽载入不覆盖当前进度；跨核心存档标明限制 |
| 内容管理 | 目录及格式说明、手动刷新、缺 BIOS 提示 | 导入失败保留原文件；禁止扫描时删除用户内容 |
| 电量不足 | 提示并允许保存；按已验证阈值安全关机 | 阈值由电芯和负载测试确定，不能照抄旧 DTS |
| 系统设置 | 语言、亮度、音量、输入校准、关于、关机 | 恢复设置不等于清除内容；删除数据需单独确认 |
| 关于/诊断 | 产品 ID、硬件/屏配置 ID、固件版本、卡状态 | 用户能拍照提交有效版本信息，不暴露无关个人数据 |

候选热键：FN+START 退出、FN+X 游戏菜单、FN+R1 保存、FN+L1 载入。软件团队须确认所选前端、核心和独立模拟器均能实现后冻结；任何未实现项必须改说明，不能只改键帽。单按 FN 不触发退出或载入。

## 4. 可直接执行的核心验收表

测试前填：样机编号、PCB/BOM 版、屏/电池料号、系统卡批次、镜像 SHA-256、环境温度、测试人员。下表每项都记录“通过/失败/未测”和证据路径；未测不能计入通过率。

| 用例 ID / 对应原需求 | 前置与操作 | 通过标准 | 执行阶段 |
| --- | --- | --- | --- |
| AT-01 / SYS-01 | 正常电量、固定卡与固件；每轮安全关机后冷启动，共 30 轮/台 | 全部进入可操作前端，无白屏、花屏或启动挂起 | EVT、DVT |
| AT-02 / SYS-02 | 取出内容卡启动；再用空内容卡启动 | 均可进入菜单、显示卡状态和正常关机 | EVT |
| AT-03 / UI-02 | 导入中文/英文/长文件名和缺封面记录，逐条浏览 | 标题可辨认、无崩溃、可返回 | EVT、DVT |
| AT-04 / UI-03 | 收藏、启动内容、退出并重启 | 收藏和最近游玩保留，路径有效 | EVT |
| AT-05 / IN-01 | 每个物理键按 20 次；方向+两动作键组合各 20 次 | 无错位、漏键、非预期连发；组合结果正确 | 裸板和装壳各一次 |
| AT-06 / IN-02 | 校准四轴，回中心静置 60 秒，再沿边界转动 | 无菜单漂移；四轴方向、范围、回中正常 | 每次摇杆/结构变更 |
| AT-07 / IN-03 | 每个首发核心执行全部热键；再执行单 FN | 全部符合冻结的热键表，单 FN 无破坏操作 | EVT、软件回归 |
| AT-08 / 存档功能 | 每个核心创建原生/即时存档，退出、关机、重启再加载 | 支持的两类存档可用；不支持项有明确说明 | EVT、DVT |
| AT-09 / UI-05 | 放入一个损坏文件、一个不支持格式，再扫描 | 不删除原文件；可见错误并返回列表 | EVT |
| AT-10 / 音频 | 扬声器/耳机、静音/多档音量、插拔、充电时播放 | 路由符合设计；无可重复爆音/严重底噪；记录音源与音量 | EVT、DVT |
| AT-11 / 电源 | 标准电源与两种 Type-C 插头方向；按定义验证 A-to-C/C-to-C | 只有经验证的组合进入兼容表；无异常发热、反灌或重启 | 硬件联调、DVT |
| AT-12 / 低电 | 按安全测试流程放电并保持记录，执行保存和关机 | 提示与关机策略生效；已完成保存的文件重启可读 | DVT |
| AT-13 / SYS-06 | 第二名人员按发布说明在备用卡恢复 | 使用规定镜像能完成启动、显示、输入、声音、充电检查 | DVT、发布前 |
| AT-14 / 设置 | 修改语言/音量/亮度，再重启及恢复默认 | 持久化和恢复符合说明，用户内容/存档未被删除 | EVT |
| AT-15 / 诊断 | 使用用户界面获取版本及存储信息 | 售后可据此找到唯一对应镜像和硬件组合 | DVT、产测 |

## 5. 性能与续航：先定测法，再冻结数字

以下全部是**新产品的建议门槛**，不是照片样机的实测结果。若与[原需求书](01_PRODUCT_REQUIREMENTS.zh-CN.md)中的候选目标不同，应由产品评审统一，不能让供应商自行选择较宽松的一项。

| 指标 | 建议立项目标 | 统一测试口径 |
| --- | --- | --- |
| 启动 | 普通冷启动到可操作菜单 ≤45 秒 | 固定卡型号和内容库；记录 30 次，列最大值及中位数；首次扩分区另测 |
| 列表响应 | 固定 1,000 条元数据的本地库，常用页面切换 ≤1 秒 | 固定封面尺寸、主题、卡和扫描状态；录像计时，不与全库扫描混测 |
| 首发模拟性能 | 选定标准片段，速度保持约 100%，无持续可闻音频断裂 | 每平台至少 3 项不同负载内容，各 30 分钟；记录内部速度和帧时间 |
| 持续稳定性 | 连续 4 小时代表性负载无崩溃和非预期重启 | 记录温度、频率、负载、声音和电量；不以静止菜单代替游戏负载 |
| 续航 | 候选 ≥3 小时正常游玩 | 指定实际屏亮度、音量、内容、室温和关机策略；满充后到安全关机 |
| 重量 | 候选 ≤250 g | 完整电池、两张卡及最终壳体，说明是否含腕带 |
| 热与充电 | 不在资料不足时编造温度/电流上限 | 按电芯、PMIC、外壳材料和目标市场要求冻结，边充边玩单独验证 |

60 fps 画面不等于模拟速度 100%；某些原平台本来就不输出 60 fps。PSP 等扩展平台必须形成逐作品支持表，说明分辨率、跳帧、核心和已知问题。

## 6. 从需求到缺陷关闭

每条需求建立一行追踪：`需求 ID → 硬件/结构/软件任务 ID → 测试用例 → 样机/版本 → 证据 → 缺陷 → 关闭人`。例如 `IN-02 → ME-07/HW-INPUT/SW-INPUT → AT-06 → 样机编号 → 四轴日志/录像`。

| 严重度 | 示例 | 退出条件 |
| --- | --- | --- |
| S0 | 电池/充电异常、持续过热、非预期电源风险 | 停止相关试验并修正；禁止带问题进入下一阶段 |
| S1 | 无法启动、频繁崩溃、存档丢失、核心按键不可用 | 根因定位、修复并完成相关全链回归 |
| S2 | 局部 UI 错误、个别作品异常、有明确绕行方式 | 有范围、责任人、修复版本；是否允许暂缓由产品签定 |
| S3 | 轻微外观/文案建议 | 进入排期；不影响已冻结的用户合同 |

首版放行要求：全部 P0 有验证证据、S0/S1 为零、未关闭 S2 有明确处理决定，恢复流程由第二人成功复核。测试样本有限不能推算批量故障率。

## 8. 本周可以领取的产品任务

1. 产品负责人填完 DEC-01～08 的已知项，未知项写负责人和日期；建立一个首版配置 ID。
2. 测试人员选定首发平台的合法测试内容，记录哈希、片段和负载；建立 AT 表格并保留原始证据。
3. 软件与产品共同走通一个“启动—运行—存档—退出—关机—再恢复”的完整流程，先消除 S1。
4. 完成 5 名试用者的 30 分钟操作观察：首次找内容、保存、退出、音量和关机，记录错误次数及具体动作。
5. 用实际结果修订候选指标，进入 G0 或 EVT 评审；不得将本文件的建议数值直接写成出厂实测规格。
