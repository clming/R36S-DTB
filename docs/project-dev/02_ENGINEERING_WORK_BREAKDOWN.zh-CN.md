# 竖式 Linux 掌机研发工作分解与工程交付规格

版本：V0.1；日期：2026-10-28。对应[产品需求书](01_PRODUCT_REQUIREMENTS.zh-CN.md)，推进方案见[快速研发路线](03_FAST_DEVELOPMENT_PLAN.zh-CN.md)。本文面向结构、电子、BSP、应用、测试和制造团队，说明为做出该产品必须完成哪些工作、交付什么、怎样判定完成。

**当前状态：只有外观附图、设备树参考及部分历史二进制，没有完整原理图、PCB、机械 CAD、量产 BOM 或可复现整机固件。** 下文的总原理图为系统连接定义与分册任务，不能替代可投板的 ECAD 图纸；器件为设计候选，不能视为已确认的附图原机 BOM。

## 1. 总体架构和跨专业接口

建议以“RK3326 级计算平台 + 4:3 屏 + 实体输入 + 可移除存储 + 可充电电源 + Linux 前端/模拟器”作为第一轮架构。采用成熟主板时仍要核验接口与来源；自行设计主板时下列电路工作全部需要完成。

### 1.1 总原理图应表达的连接

| 主连接 | 组成与方向 | 必须落实的接口约束 |
| --- | --- | --- |
| 电源主链 | USB-C 输入 → 输入保护/电流管理 → 充电及电源路径 → 系统供电；电池经保护连接到电源路径 | 区分电芯 BAT 与系统 SYS 节点，明确供电角色、反灌保护、限流和上电时序 |
| 运算与内存 | SoC ↔ DDR；SoC ↔ 时钟/复位；SoC ↔ PMIC | 电源域、DDR 类型/位宽/容量/拓扑、启动初始化、散热 |
| 存储 | SoC SD/MMC 控制器 ↔ 系统 microSD；第二控制器 ↔ 内容卡（如采用） | 各卡电压、总线宽度、时钟、检测、上拉和启动优先级 |
| 显示 | SoC DSI → 屏 FPC；电源 → LCD；背光驱动 → LED；GPIO → RESET；PWM → 背光控制 | 逐针定义 lane/polarity、地、逻辑电平、供电、时序、连接器方向 |
| 输入 | 数字键 → GPIO；四个摇杆模拟轴 → ADC/模拟多路器；可选输入 MCU → USB/I²C | IO 电压、上下拉、去抖、ADC 满量程、事件映射；两条输入方案择一冻结 |
| 音频 | SoC I²S ↔ codec；codec → 耳机/扬声器驱动 → 负载 | 若选 PMIC 内置 codec，确认是否仍需外部功放，不重复叠加功能 |
| USB 数据/外设 | SoC USB ↔ 连接器、角色检测、受控 VBUS 开关 | 明确充电专用、设备模式或主机模式；不同角色不能仅靠同形接口混用 |
| 调试与制造 | UART、测点、恢复入口、板版本识别 → 工装 | 调试电平和引脚、产测程序、序列号/版本载体、故障恢复路径 |

### 1.2 结构与电路共同维护的接口控制表

每个外设一行：`模块ID / 完整料号 / 图纸版本 / 连接器料号 / Pin1方向 / 各针网络 / 电压域 / GPIO或总线 / DTS路径 / 驱动 / 安装基准 / 负责人 / 验证状态`。该表优先于口头接线约定。

例如屏接口不可只写“40-pin MIPI”；要明确每针、电源与地、接触面、排线厚度、锁扣方向、逻辑供电和 LED 回路。屏连接器相同不代表电气兼容。电池连接器需记录正负极、线序和温度检测脚，不以外壳形状判定极性。

### 3.3 电源、USB、DDR 和高速信号的重点工作

1. 建立每路电源的负载表：电压范围、平均/峰值电流、启动冲击、时序、待机状态、效率、测点和供电裕量。CPU、DDR、LCD、背光、音频与 USB 外设分项测量。
2. 电池方案先固定电芯规格，再确定充电电压/电流、NTC、保护与软件阈值；不从旧 DTS 直接复制电池容量、OCV 表或充电参数。
3. 对 USB-C 充电专用口，按 sink 参考设计实现 CC；若需主机/设备切换则增加角色与 VBUS 管理。普通 USB 2.0 sink 的 CC 设计参考 [Synopsys 的 Type-C 实现说明](https://www.synopsys.com/articles/implementing-usb-type-c.html)，具体电路仍按选定控制器和连接器资料设计。
4. 边充边玩必须评估输入功率分配、系统峰值、电池发热与充电终止，不能只接一个充电芯片就宣称支持。
5. DDR 类型或拓扑变化需同步验证启动阶段训练/初始化、板级走线和内存压力测试；它不只影响 Linux DTS。需要原厂硬件设计约束和有经验的布局工程师。
6. DSI、DDR、USB、SD 的阻抗、参考平面、长度与间距按具体平台及板厂叠层确定。本阶段不虚构统一等长值或层数；比较可制造叠层后冻结。
7. 屏幕电源、PMIC、电池、USB VBUS、时钟和 DDR 均留测点。UART 电平必须确认，禁止默认按 5 V 串口连接。

## 4. 软件设计：从芯片启动到模拟器

### 4.1 必须交付的完整软件层次

| 软件层 | 实际工作 | 产物与依赖 |
| --- | --- | --- |
| 启动前置固件 | 按 SoC 与 DDR 配置选择初始化/信任固件，确认来源和重分发条件 | 平台可能需要的 DDR/SPL/TPL/BL31 等，具体组合由启动方案确定 |
| U-Boot | 板级配置、启动介质、屏启动可选、加载路径、恢复入口 | 引导二进制、板级配置、源码提交、烧录位置说明 |
| Linux 内核 | 内核分支、defconfig、补丁、显示/输入/音频/电源/存储驱动 | `Image`、必要模块、版本、源码、配置和构建日志 |
| 设备树 | SoC/主板/屏/外设连接、GPIO、供电、时钟、状态 | DTS/DTSI、DTB；支持 overlay 时另交 DTBO 及明确加载方法 |
| 根文件系统 | init、设备节点、库、字体、音频、图形、挂载、服务 | 可重建 rootfs；可写数据与系统文件分离 |
| 图形/音频用户态 | DRM/KMS、EGL/GLES、SDL、ALSA 等按选型集成 | 与内核 ABI/驱动匹配的用户态库及测试程序 |
| 前端 | 游戏库、主题、输入导航、设置、启动器、异常恢复 | 固定分支的 EmulationStation 类前端或自主前端，配置/补丁/素材来源 |
| 模拟器 | RetroArch、筛选后的 libretro 核心、必要的独立模拟器 | 每平台对应二进制、来源、版本、设置、测试与许可记录 |
| 系统服务 | 电量提示、热键、亮度、关机、存档同步、诊断与产测 | 服务/脚本及明确权限，不依赖手工终端配置 |
| 镜像构建 | 分区、引导布局、首次扩容、版本、校验、恢复 | 整卡 `.img` 或约定压缩包、SHA-256、manifest、制作脚本和说明 |

Rockchip 的前置二进制可从 [rkbin 官方仓库](https://github.com/rockchip-linux/rkbin) 追查，但不同板和 DDR 的组合不能随意混用。本仓库没有提供上述完整软件构建链。

### 4.2 Linux 内核镜像的具体任务

1. 从原机/供应商收集 `uname -a`、内核配置、启动日志、GPU 驱动、模块目录、BSP 源码与固定提交；不要只接收一个 `Image`。
2. 冻结一条内核路线：成熟供应商 BSP 优先保证样机；后续若迁移主线内核，单独评估驱动和图形栈。不能把旧 BSP DTB 默认用于主线内核。
3. 验证 DRM/DSI、背光 PWM、joypad 或标准输入、ADC、ALSA、RK817、电池、MMC、USB、CPU 调频和温控。根据实际需要开启功能，而非按节点存在就声称支持。
4. 构建内核及模块，模块与 `uname -r`、符号和配置匹配；验证 GPU 内核驱动和用户态库配套，保留许可证和二进制来源。
5. 完成冷启动、关机断电、按键、显示、声音、充放电、热与长时间运行。内核能启动不等于产品验收。

### 4.3 设备树的具体任务

以 [Panel4.dts](../../DTS/Panel4.dts) 为阅读起点，而不是直接当新板最终文件。既有分析见 [Panel4 DTS 与内核分析](../PANEL4_DTS_KERNEL_ANALYSIS.zh-CN.md)。

| 模块 | 参考节点/属性 | 修改与验证工作 |
| --- | --- | --- |
| LCD | `/dsi@ff450000/panel@0` | 按屏厂资料配置 lane、格式、初始化、复位、电源与延时；逐条验证命令长度 |
| 时序 | `display-timings`、`native-mode` | 追踪 phandle 并计算刷新率；Panel4 当前悬空 `0xa0` 引用须在实际适配分支中审查处理 |
| 背光 | `/backlight`、PWM、regulator | 比较实际接线与电压，验证亮度范围、频闪、噪声和开关顺序 |
| 按键 | `/odroidgo3-joypad/sw*`、`/odroidgo3-keys` | GPIO 对应物理键，事件码与驱动一致，再配置前端；不能仅改 label |
| 摇杆 | `amux-*`、ADC、轴参数 | 确认线路与 ADC 范围，校准中心、方向、死区、满量程 |
| 电源 | PMIC、battery、charger、regulator | 全部来自新板与电池依据，不复制旧参数；记录充放电测量 |
| USB/存储/音频 | 控制器、VBUS、卡检测、codec、声卡 | 验证引脚复用、供电与角色，Panel4-V22 USB 配置不能无依据照搬 |

若使用本仓库展开式 DTS 进行适配，必须检查数字 phandle、`__symbols__`、端点、`native-mode` 的所有引用。新产品在允许使用的源码基础上建议组织为 SoC 公共 DTSI + 自有主板 DTS + 明确屏版本；是否启用 overlay 由目标 bootloader/内核决定。

修改后的纯 DTS 在 Linux/WSL 的验证示例（进入本仓库根目录，已安装 dtc）：

```bash
work_dir=$(mktemp -d)
dtc --version
dtc -I dts -O dtb -o "$work_dir/panel4-candidate.dtb" DTS/Panel4.dts
dtc -I dtb -O dts -o "$work_dir/panel4-roundtrip.dts" "$work_dir/panel4-candidate.dtb"
sha256sum "$work_dir/panel4-candidate.dtb"
```

每步检查退出码，保留警告，区分原有与新增问题。没有 `-f` 强制输出。含 C 头文件、宏和 include 的内核 DTS 应使用对应内核构建系统预处理并构建，不能把上述命令当成对所有 DTS 通用。编译成功和回读正确都不代替硬件测试。

前端与模拟器是不同层。[EmulationStation 上游](https://github.com/Aloshi/EmulationStation) 可用于理解前端职责，实际应锁定经测试的维护分支；[RetroArch](https://github.com/libretro/RetroArch) 是核心运行和交互框架，核心需逐个选择；[PPSSPP 官方开发资料](https://www.ppsspp.org/docs/development/getting-started/) 可作为 PSP 扩展来源，但不承诺 RK3326 全游戏满速。

### 4.5 构建、镜像与恢复工具

建议建立独立固件工程，提交配置、补丁、哈希与打包逻辑；不要把电脑上手工改好的一张卡作为唯一母版。[Buildroot 手册](https://buildroot.org/downloads/manual/manual.html) 提供项目定制和构建机制，[genimage](https://github.com/pengutronix/genimage) 可用于生成分区和整卡镜像。这是拟建立的系统，本仓库当前没有这些构建文件。

| 事项 | 设计要求 |
| --- | --- |
| 分区 | 记录引导原始区域、启动分区、rootfs、可写数据/内容；大小由镜像和扩展计划确定，避免硬编码来源不明的扇区偏移 |
| 版本 | 关联主板 ID、屏料号/配置 ID、BOM 版本、U-Boot/内核/DT 提交、rootfs、前端及核心版本 |
| 可重建 | 固定工具链与配置；保存依赖来源与下载校验；构建结果可由第二台干净环境重建并验证关键内容 |
| 恢复 | 首版支持备用卡整镜像恢复；在线升级和 A/B 回滚如未实现，不在产品中宣称 |
| 发布 | `.img`/压缩文件、SHA-256、manifest、兼容硬件列表、已知问题、恢复步骤、组件来源和所需源码 |

烧录分两类，不能混为一谈：

- **microSD 整卡镜像**：用 [balenaEtcher 官方项目](https://github.com/balena-io/etcher) 等成熟工具，选择整卡镜像和正确物理卡，写入并验证。研发和售后优先采用此路线；量产需有批量写卡、校验和记录工具。
- **板上存储/USB 恢复**：仅在硬件和启动方案具备相应条件时，使用 [Rockchip rkdeveloptool](https://github.com/rockchip-linux/rkdeveloptool) 配合匹配 loader、模式和存储布局。Type-C 接口存在不代表支持 MaskROM/Loader 烧录，更不能从其他板复制偏移或 loader。

写卡前备份，核对卡容量和目标设备；首次只使用备用卡、一次验证一组配置。修改现有系统仅改必要的 DTB 加载项，保留原 `root=`/UUID/加载地址/内核/initrd。失败后关机取卡恢复原文件；内核变化时同时恢复配套模块。本文未执行任何烧录。

### 5.2 团队和关键依赖

建议至少明确产品/项目、结构、电子/PCB、BSP、应用、测试/制造六类责任；小团队可兼岗。采购成熟主板可减少 PCB 与底层适配工作，但不能省略来料确认、软件来源、整机验证和售后交付。
