### 1.2 产品定位

面向希望离线游玩经典游戏、使用实体按键和随身携带的玩家。核心体验为“开机进入游戏库—找到内容—启动游玩—保存进度—安全退出与关机”。产品应让没有 Linux 使用经验的人完成这些操作，不要求打开终端或修改设备树。

首版保留上屏下控、双摇杆及独立 FN 的布局特征。新品牌、开机画面、主题和内容素材独立准备。外形尺寸和内部结构以工程样机验证后冻结，不能由照片比例直接定模。

### 1.3 建议产品基线

| 维度 | 首版建议 | 决策依据/验证方式 |
| --- | --- | --- |
| 显示 | 约 3.5 英寸、4:3、640×480 彩屏，至少一个稳定约 60 Hz 模式 | 本仓库 Panel4 有 640×480 配置；3.5 英寸来自外部 R36S 平台资料，须以采购屏规格和样机确认 |
| 计算能力 | RK3326 级 Linux 平台；首轮优先验证成熟主板 | 芯片型号不作为最终性能验收替代品 |
| 内存 | 1 GB 级作为候选，最终按目标应用内存峰值确认 | 照片和本仓库不足以确认该样机 RAM 料号及容量 |
| 输入 | 十字方向、ABXY、双模拟摇杆、FN、SELECT、START、音量、电源；建议 L1/R1/L2/R2 | 四肩键为建议需求，不是从侧图确认的完整键数 |
| 存储 | microSD 启动；支持内容导入与备份；双卡为优先方案但待主板冻结 | 第一张图未证明双卡；产品应清楚区分系统和内容 |
| 音频 | 内置扬声器；音量可调和静音；3.5 mm 耳机输出优先 | 耳机接口为建议需求，非照片已确认事实 |
| 电源 | 可充电单节锂电方案；USB-C 5 V 输入作为首版设计方向 | 容量、截止电压和充电电流由电芯、整机功耗及热设计确定 |
| 外形与重量 | 候选包络约 130×85×25 mm、整机不高于 250 g | 只作空间与握持评审起点；必须通过卡尺、称重和结构样机修订 |
| 网络 | 基础功能完全离线；无线功能不列首版必需 | 避免菜单依赖未配置的联网硬件 |
| 内容交付 | 自有或获授权演示内容，用户可导入自有内容 | 不以预装游戏数量作为完成度指标 |

## 2. 目标用户和关键场景

| 场景 | 用户目标 | 产品要求 |
| --- | --- | --- |
| 首次开机 | 不连接电脑也能进入演示内容 | 显示语言、按键提示、存储状态，能启动至少一个合法演示程序 |
| 日常游玩 | 找到游戏后立即开始 | 平台分类、游戏列表、最近游玩、收藏；按键语义一致 |
| 中断游玩 | 保存后退出，下次继续 | 区分游戏原生存档与模拟器即时存档；操作成功有反馈 |
| 增加内容 | 把文件放进去就能在列表中找到 | 目录说明、支持格式、刷新入口、缺 BIOS 提示；错误不致黑屏 |
| 电量不足 | 不丢失已保存的进度 | 低电提示、停止高风险写入、按策略安全关机 |
| 更换系统卡 | 恢复机器到可用状态 | 提供对应硬件版本的恢复镜像、烧录与首次启动说明 |
| 售后诊断 | 用户能提供有效故障信息 | “关于/诊断”显示固件、硬件配置 ID、存储状态和测试入口 |

## 3. 功能需求与验收

### 3.1 启动、电源和恢复

| 编号 | 优先级 | 需求 | 验收方式 |
| --- | --- | --- | --- |
| SYS-01 | P0 | 按电源进入启动流程，自动打开前端 | 量产候选样机连续 30 次冷启动均进入可操作菜单，无白屏/花屏 |
| SYS-02 | P0 | 显示简洁启动状态与品牌画面，启动失败可诊断 | 拔除内容卡、缺少内容和正常启动三种情况能区分 |
| SYS-03 | P0 | 菜单支持安全关机；电源键行为明确 | 退出游戏、写回存档、卸载后断电；关机后不持续高功耗 |
| SYS-04 | P0 | 长按强制关机只作为故障恢复 | 独立测试并在说明中区分，正常操作不依赖强断电 |
| SYS-05 | P1 | 支持息屏/暂停；是否真正待机由功耗验证决定 | 显示实际待机功耗；不能以黑屏冒充低功耗休眠 |
| SYS-06 | P0 | 恢复镜像能在备用卡恢复基本功能 | 按公开说明由第二名测试者恢复，原始存档有备份路径 |

### 3.2 游戏库与菜单

| 编号 | 优先级 | 需求 | 验收方式 |
| --- | --- | --- | --- |
| UI-01 | P0 | 按游戏平台分类，进入游戏列表 | 空分类可隐藏；有内容的平台可由实体按键进入 |
| UI-02 | P0 | 支持中文与英文、列表滚动、封面可选、底部操作提示 | 中文文件名不乱码；缺封面时仍正常显示标题 |
| UI-03 | P0 | 最近游玩、收藏、按名称查找 | 退出并重新开机后记录保留 |
| UI-04 | P0 | 菜单确认、返回和 FN 操作全局一致 | 用按键对照表检查前端与全部首发模拟器 |
| UI-05 | P0 | 内容扫描可见进度，失败不删除文件 | 导入有效/损坏/不支持文件，结果明确且能返回菜单 |
| UI-06 | P1 | 主题可切换，默认主题适配 640×480 | 文字无溢出；禁止把第三方游戏宣传图片当自有默认素材 |
| UI-07 | P0 | 系统设置包括亮度、音量、语言、版本和关机 | 设置重启保留；恢复默认不删除用户内容和存档 |

### 3.3 输入与热键

| 编号 | 优先级 | 需求 | 验收方式 |
| --- | --- | --- | --- |
| IN-01 | P0 | 十字键四方向及斜向可用，ABXY 和肩键无错位 | 输入测试页面显示每个物理键；同时按压方向+两键不丢键 |
| IN-02 | P0 | 双摇杆支持中心校准、死区与轴方向检查 | 中心静置 60 秒无可见菜单漂移；四轴均可达到校准满量程 |
| IN-03 | P0 | FN 作为功能修饰键，有明确热键页 | 建议 FN+START 退出、FN+X 菜单、FN+R1 保存、FN+L1 载入；最终按选用前端实现冻结 |
| IN-04 | P0 | 危险操作防误触，载入/重置需保护 | 单按 FN 不退出；保存有成功反馈，载入有短提示或确认机制 |
| IN-05 | P0 | 音量侧键有效，有音量反馈 | 游戏内调节不误触退出，静音和最大音量可识别 |
| IN-06 | P1 | 按键重映射并恢复默认 | 用户错误映射后可恢复；新固件不无提示覆盖个人映射 |

FN 热键是建议产品交互，不等同于仓库已有 DTS 自动实现。左右摇杆是否带 L3/R3 按压、以及肩键数量，须拆机和选型确认后决定是否纳入首版。

### 3.4 模拟器与兼容性

首版按测试通过的“平台—核心—版本—设置—内容集合”发布能力说明。建议 NES/FC、GB/GBC、GBA、MD 和 SNES 构成首发评估范围，PS1 为重点扩展验证；PSP、N64、Dreamcast 先列选择性兼容，不承诺全库满速。此分级是立项建议，尚无本机性能测试结果。

| 编号 | 优先级 | 需求 | 验收方式 |
| --- | --- | --- | --- |
| EMU-01 | P0 | 每个首发平台至少指定一个经过筛选的默认核心 | 清单记录核心来源、许可、版本、BIOS 依赖、默认视频和音频参数 |
| EMU-02 | P0 | 启动/退出可恢复，异常游戏不拖垮整个前端 | 模拟器崩溃后回到菜单，留下错误记录 |
| EMU-03 | P0 | 游戏原生存档及支持核心的即时存档可读写 | 每个核心各做保存、关机、开机、读取；不承诺跨核心/跨版本即时存档兼容 |
| EMU-04 | P0 | 保持正确比例，提供整数缩放或等比例缩放 | 4:3 与掌机平台画面均不被强行拉伸；用户可选择 |
| EMU-05 | P1 | 截图、快进、滤镜按平台开放 | 快进不能作为正常速度性能达标的替代；高负载滤镜默认关闭 |
| EMU-06 | P0 | 缺 BIOS、文件损坏、格式不支持时有可理解提示 | 返回游戏列表，原文件不被自动删除 |

### 3.5 存储、音频、充电

| 编号 | 优先级 | 需求 | 验收方式 |
| --- | --- | --- | --- |
| DATA-01 | P0 | 明确系统、内容、存档、设置的存放和备份方式 | 用户能按说明备份并在相同固件恢复；不要求备份整个游戏库才能备份存档 |
| DATA-02 | P0 | 选择一种经过验证的用户导入方式 | 首版优先关机取内容卡；USB 数据导入若未实现则不显示该功能 |
| DATA-03 | P0 | 卡满、只读、卡缺失可见且不导致无限重启 | 故障注入并验证菜单仍可关机和查看原因 |
| AUD-01 | P0 | 扬声器无明显破音、静音无持续明显噪声 | 指定音频样本和音量档位主观/仪器测试，插充电器复测 |
| AUD-02 | P1 | 耳机插入切换输出，拔出恢复 | 有耳机硬件时验证左右声道及插拔；无此硬件时删除相关宣传 |
| PWR-01 | P0 | 电量与充电状态可见 | 充电、放电、满电、低电四种状态一致；电量算法需校准 |
| PWR-02 | P0 | USB-C 5 V 充电，正反插均正常 | A-to-C 与 C-to-C 分别测试；不宣称快充或 PD，除非硬件已实现并验证 |
| PWR-03 | P0 | 边充边玩为目标，必须验证温升与电源稳定 | 高负载下充电不反复重启、不超电芯和器件允许条件 |
| PWR-04 | P0 | 低电保护提前于硬件断电执行 | 不同负载下重复测试，保存记录后安全关机；阈值由验证确定 |

## 4. 可量化体验目标

下表是评审起点，应在样机基线测试后冻结。测试报告必须记录硬件版本、固件哈希、卡型号、负载、环境、样本数和测量方法。

| 指标 | 建议首版目标 | 测试条件 |
| --- | --- | --- |
| 冷启动 | 常规启动至可操作菜单 ≤30 秒；首次扩容单独记录 | 从电源触发计时；同一合格卡型号，10 次测量报告最大值 |
| 前端交互 | 菜单按键响应 P95 ≤150 ms | 用 240 fps 视频或等效测量方法，至少 100 次按压 |
| 内容列表规模 | 5,000 条本地元数据下可正常滚动，列表切换 ≤2 秒 | 合成或合法测试元数据，不要求加载全部高清封面到内存 |
| 基础平台运行 | 测试集各内容保持其原生帧率的 ≥95%，音频无持续爆音 | 每平台建议 10 个合法样本，每个运行 15 分钟，固定核心/设置；PAL/NTSC 分别判定 |
| 连续运行 | 8 小时混合负载无崩溃、无持续降频导致验收失败 | 稳定供电和电池测试分开；保留温度和频率日志 |
| 电池续航 | 标准负载至少 4 小时作为目标 | 25±2℃、亮度约 50%、音量约 30%、固定游戏及核心；电芯容量实测后复核 |
| 发热 | 正常握持区域目标 ≤42℃ | 25±2℃，高负载运行 1 小时；同时遵守电芯及器件自身限值，不能只看外壳温度 |
| 输入耐用 | 主按键 10 万次作为开发验证目标 | 依据实际按压力和行程设计工装，测试后无连击/卡滞；非现有寿命数据 |
| 插拔耐用 | USB-C、卡座按供应商额定值制定整机抽测 | 受力包含接口支撑和外壳开口，不能只接受连接器目录参数 |
| 运输/跌落 | 候选 0.8 m 六面工程跌落后功能可用 | 指定地面和样本；结构样机阶段先验证方案，不将估计值当认证结论 |

续航应按能量预算估算：`续航 ≈ 电芯标称电压 × 实测容量(Ah) × 可用系数 / 电池侧平均功耗(W)`。例如假设 3.7 V、3 Ah、可用系数 0.85、平均 2.3 W，估算约 4.1 小时；这些数值仅示范计算，不是本产品已选电池或实测功耗。

## 5. 外观、结构与可维护性

1. 上部屏幕需有保护镜片、遮光和可靠固定；视区不得被装饰边框遮挡。半透明壳体需评估灯光串光、内部线束与胶位外观。
2. 左手拇指能切换十字键与左摇杆，右手能切换 ABXY 与右摇杆；肩键不要求改变正常握姿。用手板和至少 5 名试用者验证，不能仅按照片坐标布置。
3. 音量键应可辨方向；电源键防误触；卡座和接口丝印清楚，不能让用户把充电口当成未实现的数据口。
4. 电池固定、排线防折和扬声器声腔需独立设计。不得让电池成为螺柱、尖角或按键的受压件。
5. 首版采用可拆螺钉结构，维修可更换屏幕、电池、摇杆；是否开放用户换电池需结合实际结构和售后策略决定。
6. 开机/充电灯不能直射眼睛或透过屏幕明显漏光；指示状态必须在说明中一致，不将蓝光颜色本身当成技术需求。

| 生产 | 烧录校验记录、整机产测结果、批次追溯 | 制造/测试 |
| 内容与来源 | 组件来源/许可清单、自有或已获授权的主题/游戏/BIOS 素材 | 项目/发布 |
| 用户材料 | 快速上手、热键表、导入目录、低电行为、恢复和售后入口 | 产品/售后 |

## 8. 立项时必须冻结的决策

| 决策 | 当前建议 | 最晚冻结点 |
| --- | --- | --- |
| 是外观体验复现，还是连主板也独立设计 | 先成熟主板做整机，再决定是否自研主板 | 样机采购前 |
| 目标用户、售价、首批数量 | 当前未定；先收供应商分档报价，不用市场零售价推导 BOM | 商务立项 |
| 单卡/双卡、耳机和 USB 数据口 | 优先按成熟可供方案评估，明确用户交互 | 结构堆叠冻结前 |
| 屏幕与电池规格 | 单一主料号起步，要求可追溯批次 | EVT 投板/首轮机构样机前 |
| 商业出货的软件来源 | 从有明确来源和可履约许可的组件构建或取得授权交付 | 固件基线冻结前 |
| 后续维护期限 | 建议至少覆盖一个产品销售与售后周期，具体年限由经营计划确认 | 量产发布前 |

这份需求书是新产品定义，不是对附图原机的拆机报告，也不授权直接沿用原机品牌、主题和游戏素材。研发完成以以上功能证据为准。
