## 1. 项目概述

在一台 R36S 掌机（屏幕由 3.5 寸升级为 4.0 寸）上加装蓝牙音频能力，通过一个新增的
物理按钮在两种模式间来回切换：

- **游戏模式**：原 ArkOS 系统原样运行；游戏音频可通过蓝牙音箱播放。
- **音箱模式**：掌机变成一台蓝牙音箱，手机连接后用手机音乐 App 播放，本机扬声器
  出声；屏幕显示多风格表盘（≥8 种，部分带歌词/音频频谱/动画显示，全部含时间与
  环境温度显示）、支持闹钟（含关机闹钟唤醒）；歌词由手机音乐 App 经蓝牙推送
  （v0.5 主方案，见 FR-7）；原游戏按键复用为播放/暂停、音量、表盘切换；整机设一个
  RGB 氛围灯（单颗 WS2812B，全彩渐变）。
- **麦克风**：拾取环境声供频谱表盘渲染（v0.5 定位）；蓝牙免提通话（HFP）为可选
  扩展（P2），失败可裁剪。
- **温度传感器**：独立环境温度传感器（H11），表盘显示环境温度；SoC 温度仅作设置
  页诊断。
- **表盘第三方编辑**：表盘为开放 JSON 格式（对齐 Divoom AstroToo 声明式图层设计
  范式），第三方可手写编辑或用 PC 工具制作导入（FR-10）。
- 全机**无触摸**（屏幕暂不带触摸功能），所有交互通过物理按键/摇杆完成。

**存储架构（v0.4 明确）**：**单 TF 卡方案**——一张 SD 卡同时承载 ArkOS 2.0 系统、
游戏模拟器与 ROM、蓝牙播放器资源（表盘配置 / 歌词库 / 铃声）。不使用双卡分工；
ArkOS rootfs 可写，自研软件放独立目录经 custom.sh 挂载（防 OTA 覆盖）。

另新增一个 2.4G 无线手柄用于双人游戏。

## 2. 现状基线（R36S 硬件）

| 项目 | 规格 | 对本项目的意义 |
|---|---|---|
| SoC | RK3326（4×Cortex-A35，64 位）+ Mali-G31 MP2，1GB RAM | 够跑 ArkOS + bluez 音频栈 |
| 无线 | **无 WiFi、无蓝牙** | 必须走 USB dongle 路径 |
| 接口 | 2×USB-C（1 个 OTG + 1 个仅充电）、3.5mm 耳机 | OTG 口是全部外设的唯一入口 → 需内置 hub |
| 屏幕 | 3.5 寸 640×480 IPS，MIPI DSI 接口 | 换 4.0 寸需匹配接口与时序 |
| 扬声器 | 单声道 | 音箱模式出声通道 |
| 系统 | ArkOS（Ubuntu rootfs，rootfs 可写，有 custom.sh 持久化钩子） | 可加装自研守护进程与软件包 |
| 电池 | ~3500mAh | BT dongle 为主要功耗增量，需做功耗预算 |

## 4. 功能需求（FR）

### FR-1 模式切换（物理按钮）
- 按一下切换按钮：游戏模式 → 音箱模式；再按一下：音箱模式 → 游戏模式。
- 切换动作（≤2s 内完成）：启停对应服务（EmulationStation / 表盘 App / 蓝牙音频栈）、
  切换音频路由、切换 RGB 灯效主题。
- 防误触：默认长按 1s 触发切换（可配置）。

### FR-2 游戏模式（ArkOS 原生 + 蓝牙出声）
- ArkOS 全部原有玩法、按键功能不变。
- 游戏音频路由可三选一：本地扬声器 / 蓝牙音箱（A2DP source，本机做音源）/ 关闭。
- 蓝牙音箱断连时自动回退本地扬声器。

### FR-3 音箱模式（本机 = A2DP sink；HFP 免提为 P2 可选）
- 本机注册为蓝牙音箱设备（如 "R36S Speaker"），手机搜索配对。
- 音源为手机音乐 App；声音从本机扬声器播放。
- 播放/暂停按键通过 AVRCP passthrough 控制手机端播放器。
- **内置麦克风（v0.5 定位调整）**：经 H9 USB 声卡接入，主用途为频谱表盘拾音
  （FR-6/FR-9 频谱数据源）；HFP 免提通话降级为可选扩展（P2）——实现时手机来电
  本机响铃（扬声器），A 键接听、B 键挂断，麦克风拾音经蓝牙上行回手机；通话与音乐
  播放互斥，来电优先切 HFP，结束回 A2DP。

### FR-4 音箱模式按键复用映射（草案，可调整）

| 原按键 | 音箱模式功能 |
|---|---|
| A | 播放 / 暂停（闹钟响铃时 = 停止闹钟；来电响铃时 = 接听，见 FR-3） |
| B | 贪睡 5 分钟（仅闹钟响铃时有效；来电响铃时 = 挂断） |
| R2 | 音量 + |
| L2 | 音量 − |
| 左摇杆 | 切换表盘风格；设置菜单内调节数值 |
| SELECT + START | 进入 / 退出闹钟及时间设置菜单 |
| 长按切换按钮 | 回游戏模式 |
| 其余按键 | 不响应（避免误触） |

### FR-5 RGB 氛围灯（整机单灯）
- 整机 1 颗 WS2812B，全彩渐变（呼吸 / 色相流转 / 模式联动变色）。
  （v0.3 简化：原"每键独立灯效、各键颜色相位不同"需求取消。）
- 灯效主题随模式切换：游戏模式 = 静态低亮或关闭；音箱模式 = 多彩渐变。
- 音乐律动灯效（P1，v0.5 新增）：音箱模式播放时灯色随麦克风频谱起伏（与频谱表盘
  同源数据），设置中可关闭。
- 亮度可调；单颗功耗可忽略，不再设 30% 上限约束。
- 工艺：R36S 外壳不透光，灯置于机内透光位或开 1 个小导光孔。

### FR-6 表盘 UI（≥8 种风格，全部带时间显示）
- 4 寸屏全屏显示；**无触摸**，全部交互经物理按键/摇杆完成；风格观感对齐 Divoom
  AstroToo 的像素/图层设计语言（表盘格式同构，见 FR-10）。
- 至少 8 种风格，**每种风格必须包含时间显示**：
  1. 极简数字钟（大字号时分，可显示秒）
  2. 模拟表盘（指针式）
  3. 复古像素风
  4. 翻页时钟
  5. 歌词大字报（时间 + 歌词滚动，见 FR-7）
  6. 仪表盘风（转速表视觉风格，时间 + 播放状态）
  7. 霓虹渐变（与 RGB 氛围灯联动）
  8. 播放信息版（时间 + 曲名/歌手/专辑 + 进度条）
  9. 音频频谱（时间 + 实时频谱柱状/波浪动画，数据取自 H9 麦克风拾音 + FFT，
     v0.4 新增、v0.5 数据源改为麦克风）
  其中 5、6、8 为带歌词/播放信息显示的风格；9 为动态视觉效果风格。
- 左摇杆左右切换风格；当前风格记忆保存（重启保持）。
- 蓝牙未连接时显示"等待连接"状态；各风格角落显示蓝牙状态、电量与 **环境温度**
  （v0.5 改为 H11 传感器读数，精度 ±0.5°C、分辨率 0.1°C；SoC 温度移至设置页诊断，
  超温告警保留在诊断页）。
- 动画元素：复古像素/翻页等风格含帧动画；表盘 JSON 支持帧序列/GIF 资源与动画参数
  （对齐 Divoom image/GIF 资源通道，见 FR-10）。

### FR-7 歌词显示
- 带歌词的表盘风格需按 LRC 时间轴同步滚动显示歌词。
- 歌词数据源按优先级（v0.5 重排：蓝牙推送为主方案）：
  0. **AVRCP 私有歌词协议（P0 主方案）**：标准 AVRCP 无歌词字段，但网易云/QQ音乐/
     酷狗等手机音乐 App 通过 AVRCP Vendor-Dependent 私有命令向接收端推送歌词行
     （即各 App 自带的"车载蓝牙歌词"功能），国产蓝牙芯片（杰理 JL、中科蓝讯）SDK
     内置配套解析。本机为接收端（音箱角色），在 bluez 栈中自实现 vendor 命令解析器
     直接接收（社区已有 HCI 抓包逆向资料）。局限：仅 Android + 指定 App 并打开
     "车载蓝牙歌词"开关；iOS 不允许第三方 App 注入自定义 AVRCP 命令。无需 WiFi、
     无需在手机端安装任何新 App。
  1. **本地 LRC 歌词库（P1 离线备选）**：SD 卡 /lyrics 目录，按"曲名 - 歌手"匹配；
     LRC 在 PC 上批量下载后拷入，本机全程离线可用；覆盖 iOS 及未开车载歌词场景。
  2. ~~在线歌词接口~~（v0.5 取消：全机无 WiFi）
  3. ~~手机伴侣 App 推送~~（v0.5 取消：明确不做手机端专用 App）
- 技术约束：标准蓝牙 AVRCP（1.3~1.6）元数据白名单只有曲名/歌手/专辑/流派/时长/封面，
  **不含歌词字段**；因此歌词只能走（a）App 私有 vendor 命令推送（v0.5 主方案）或
  （b）本机按曲目元数据匹配本地 LRC 文件（备选）。存在另一非标准做法：个别实现把
  当前歌词行反复写入"曲名"属性，任何能显示曲名的设备都会跟随滚动——兼容性好但
  污染曲名显示，不作首选。
- **无 WiFi 场景说明（v0.5）**：全机不配 WiFi。歌词覆盖 = 蓝牙推送（数据源 0，
  流媒体/本地曲库通吃，Android）∪ 本地 LRC 库（数据源 1，iOS 及未开车载歌词时
  兜底）；两者均不依赖网络。
- 匹配失败的曲目降级显示曲名/歌手/进度（即风格 8 形态）。

### FR-8 闹钟
- 设置：SELECT+START 进入设置菜单（纯按键操作），摇杆调数值、A 确认；
  支持 ≥3 组闹钟（每天 / 工作日 / 单次）。
- 触发：到点本机扬声器播放本地铃声文件（音量 5s 渐强）；铃声存 SD 卡可替换。
- 响铃时按键：A = 停止，B = 贪睡 5 分钟。
- 生效范围：默认仅音箱模式触发；可配置为"全局"（游戏模式下也打断响铃）。
- 闹钟强依赖系统时间准确（见 FR-9）；到点时若时间未同步则跳过并提示。
- **关机闹钟（v0.4 新增，同手机行为）**：软关机后整机断电，DS3231（H8/H10）闹钟
  中断经 MCU 触发"模拟电源键"自动开机，并直入闹钟响铃页面。实现要点：
  - 关机前 mode-daemon 将最近一组闹钟时间写入 RTC alarm 寄存器；
  - MCU 固件监听 RTC INT（低功耗待机，接电池常电轨，静态电流 µA 级）；
  - MCU 开漏输出 + 二极管隔离并联电源键线，等效"人按电源键"；
  - 开机后 mode-daemon 检测"RTC 唤醒"标志，跳过常规启动直接进入闹钟页面；
  - 若无 H10 电路，降级为"睡眠模式闹钟"（屏幕关闭 + 低功耗待机，非真关机）。

### FR-9 时间同步（闹钟/表盘的衍生需求）
- R36S **无 RTC 电池**，断电重启后系统时间丢失，必须解决时间来源（v0.5：全机无
  WiFi，取消 NTP 对时）：
  1. **主方案**：H8 DS3231 RTC 模块（I2C，必配），断电保持走时（±2ppm 级，年漂移
     分钟级）；同时承担关机闹钟唤醒的中断源（见 FR-8）
  2. 兜底：设置菜单内按键手动对时
- RTC 未安装或检测失效时，表盘显示"时间未同步"角标，闹钟不触发；手动对时后恢复。

### FR-10 表盘第三方编辑与导入（v0.5 新增正式需求）
- **开放表盘格式**：表盘 = JSON 描述 + 资源文件（图片/GIF 帧动画/字体）。JSON 对齐
  Divoom AstroToo 声明式图层范式（画布 + ItemList 图层 + disp 控件枚举 + 字体 ID，
  调研结论见《Divoom表盘JSON调研.md》）；disp 低位段语义与 Divoom 对齐，歌词滚动/
  RGB 联动/蓝牙状态用 1000+ 自定义段。阶段 3 产出 schema v0.1，随固件发布《表盘
  开发规范》文档。
- **编辑方式**：
  - P0：第三方按规范手写 JSON（文本编辑器即可制作），无需官方工具、无需账号；
  - P1：PC 可视化表盘编辑器 MVP（画布拖放 + 实时预览）+ **Divoom AstroToo 表盘
    JSON 导入转换器**（480×480 画布直映射；640×480 屏时画布字段化适配）。
- **导入**：USB OTG 连 PC → 设备 U 盘模式挂载存储分区 → 拷入表盘包 → 安全弹出后
  设备端刷新表盘列表。
- **管理**：表盘列表支持预览、应用、删除；当前表盘记忆保存（重启保持）。
- **校验与容错**：导入时按 schema 校验，非法包拒绝导入并提示失败原因（缺资源/
  字段越界/disp 未知）；渲染器对未知 disp 容错（跳过该图层，不崩溃）。
- **分发**：表盘包为纯文件，可自由拷贝分享；不建商店、不做在线分发（无 WiFi）。

## 5. 软件架构（运行于 ArkOS）

```
HID 切换按钮 ──┐
              ├─> mode-daemon（systemd 服务，evdev 监听）
原按键 evdev ──┘        │
                        ├─ 游戏模式：起 EmulationStation；音频 → bluealsa A2DP source
                        ├─ 音箱模式：起 clock-ui；bluez-alsa sink（AVRCP passthrough）
                        └─ rgb-ctl ──UART/USB-CDC──> MCU ──> WS2812B ×1
```

| 模块 | 职责 | 说明 |
|---|---|---|
| mode-daemon | 模式状态机、服务启停、音频路由切换、关机闹钟写入 RTC、RTC 唤醒标志检测 | C/Python 均可 |
| clock-ui | 表盘渲染、闹钟状态机、歌词显示、频谱渲染、环境温度/电量角标 | SDL2 全屏 + evdev 读按键；表盘以 JSON/资源包配置（FR-10 开放格式）；推送/LRC 歌词时间轴同步；频谱 = H9 麦克风采样 + FFT；环境温度经 I2C 读 H11 |
| hfp-audio | HFP 免提通话（P2 可选扩展，可裁剪） | bluez HFP 后端（oFono）+ USB 声卡上行；来电铃声 / 接听挂断事件总线 |
| lyrics-resolver | 歌词获取与同步 | AVRCP vendor 私有歌词协议解析（P0 主）→ 本地 LRC 匹配（P1 备选） |
| time-sync | 时间来源维护 | DS3231 RTC（I2C，主）→ 手动对时，二级降级；v0.5 无 WiFi，无 NTP |
| rgb-ctl | 灯效下发 | 按帧/按参数下发 MCU |
| MCU 固件 | USB 键盘（切换按钮）+ WS2812 驱动 + RTC 中断监听（关机唤醒） | CH552/STM32，单芯片兼任；唤醒待机 µA 级 |
| 持久化 | 通过 ArkOS custom.sh 钩子自启 | 防 OTA 更新覆盖 |

## 6. 非功能需求

| 项目 | 指标 |
|---|---|
| 模式切换时间 | ≤ 2s |
| 音箱模式续航 | 较纯游戏续航下降 ≤ 20%（BT dongle 为主，RGB 单灯功耗可忽略 + 待机降帧） |
| 无触摸交互 | 全部功能按键可达；设置菜单层级 ≤ 2 级 |
| 时间精度 | DS3231 RTC 走时 ±2ppm 级（年漂移分钟级）、断电不丢时；手动对时设置精度 ≤ 1s |
| 环境温度 | H11 传感器精度 ±0.5°C、分辨率 0.1°C、刷新周期 ≥ 1s |
| 频谱响应 | 麦克风采样 → 渲染端到端延迟 ≤ 100ms，刷新率 ≥ 20fps；无声时静止或隐藏 |
| 音频延迟 | 音箱模式听歌不敏感；游戏模式建议默认本地扬声器（蓝牙有 100~200ms 延迟） |
| 外观 | 除新增切换按钮外无开孔痕迹；dongle 全部内置 |
| 稳定性 | 模式异常退出可回滚（看门狗：clock-ui/ES 崩溃自动回游戏模式） |

## 7. 可行性分析

| 项 | 评级 | 依据 |
|---|---|---|
| 2.4G 手柄 | 🟢 低风险 | 成品方案，标准 USB HID，ArkOS 原生支持，大量用户实测 |
| 按键复用 + 表盘 UI | 🟢 低风险 | 纯应用层（evdev + SDL2），无硬件依赖 |
| 切换按钮 + RGB 氛围灯 | 🟢 低风险 | HID 模拟键盘与 WS2812 均为成熟方案；单灯无需复杂走线，仅需开 1 个导光孔；需自行写 MCU 固件 |
| 蓝牙双角色音频 | 🟡 中风险 | bluez + bluez-alsa 支持 sink/source 双角色，技术成熟；挑战：ArkOS 无在线包管理，需交叉编译 armhf 并静态打包；ArkOS OTA 更新可能覆盖，需 custom.sh 钩子持久化 |
| 功耗与续航 | 🟡 中风险 | BT dongle 为主要功耗增量（RGB 单灯可忽略），估算占整机功耗 10%~20% |
| 歌词显示 | 🟡 中风险 | v0.5 主方案为 AVRCP 私有歌词协议（需 HCI 抓包逆向；仅 Android + 指定 App 开"车载蓝牙歌词"），协议适配为不确定性主体；本地 LRC 匹配引擎兜底（匹配率依赖曲库命名规范）；纯展示逻辑简单 |
| 闹钟 | 🟢 低风险 | 纯软件功能（本地铃声 + 渐强播放 + 贪睡状态机），无硬件依赖 |
| 时间同步 | 🟢 低风险 | v0.5 无 WiFi，DS3231（H8）转必配主方案：成熟模块、断电走时、精度足够；手动对时兜底 |
| 麦克风频谱（H9 主用途） | 🟢 低风险 | USB 声卡采音 + FFT 纯软件链路 |
| 麦克风通话（HFP，P2 可选） | 🟡 中风险 | bluez HFP 需 oFono/HFP 后端，ArkOS 需交叉编译；回声消除靠软件（speexdsp），效果有限；独立模块，失败可裁剪不影响频谱与听歌 |
| 音频频谱表盘 | 🟢 低风险 | v0.5 数据源改为 H9 麦克风（采音 + FFT，纯软件，SDL 直绘）；无声音时静止或隐藏 |
| 环境温度显示 | 🟢 低风险 | v0.5 新增 H11 I2C 数字温度传感器（±0.5°C 级成熟方案）；SoC 温度读 /sys/class/thermal 仅作诊断 |
| 表盘第三方编辑 | 🟢/🟡 | P0 手写 JSON + schema 校验：低风险（Divoom schema 调研已完成，格式同构）；P1 PC 编辑器 + AstroToo JSON 转换器：中等工作量，纯 PC 端开发，与设备解耦 |
| **关机闹钟唤醒** | 🟡 中偏高 | 需逆向 R36S 电源键电路（MCU 开漏 + 二极管隔离并联按键线）；DS3231 闹钟中断触发；断电后 MCU/RTC 接电池常电轨（静态 µA 级）；**已列为高优先级**——电路逆向提前至阶段 0、实施安排在阶段 5；失败可降级"睡眠模式闹钟"，不影响其他功能 |
| **4.0 寸换屏** | 🔴 高风险 | R36S 面板有 4 种变体，兼容性极敏感；4.0 寸可选 640×480（4:3，需改 DTB 时序与背光）或 480×480（方形，还需 UI 适配）；接口/排线/初始化序列任一不匹配即黑屏。建议：优先找同源 4.0 寸机型的面板借 DTB；换屏与功能开发完全解耦，失败可回退 3.5 寸 |

**总体结论**：除换屏外全部可控，属于"硬件小改装 + 系统级软件定制"型项目，以你的
嵌入式背景（MCU 固件、Linux）完全可行。建议把换屏放到最后单独验证，与功能开发
解耦；项目成败关键点按顺序是：内置 hub 改装 → bluez-alsa 双角色 → 关机闹钟唤醒
（高优先级，电路逆向前置到阶段 0）→ 换屏。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| ArkOS OTA 覆盖自定义软件 | 全部自研文件放独立目录，custom.sh 挂载/自启 |
| 内部空间不足（hub + dongle ×2） | 先做实物排布演练再焊接；选最小尺寸 hub 板 |
| 4.0 寸屏黑屏/花屏 | 回退 3.5 寸 DTB；换屏前备份完整镜像 |
| RGB 电流过大拖垮电池/供电 | MCU 限流 + 低电自动关闭灯效（单颗灯电流有限，风险低） |
| 音箱模式下误触游戏按键 | 映射表白名单制，仅 A/B/R2/L2/摇杆/SELECT+START 生效 |
| 断电重启后时间丢失、闹钟失效 | v0.5：DS3231 RTC 必配，断电保持走时；闹钟触发前自检时间状态，异常则界面提示 |
| 歌词推送不可用（iOS / 未开车载歌词） | FR-7 双通道覆盖：蓝牙推送（Android）+ 本地 LRC 库兜底；引导曲库按"曲名 - 歌手.mp3/.lrc"成对命名，提供本地歌词库整理脚本 |
| 电源键电路飞线失误损坏主板 | 先画图核对电路再动手（逆向调研提前至阶段 0）；开漏输出 + 二极管隔离；失败降级睡眠闹钟 |
| 麦克风回声/啸叫（仅 HFP P2 场景） | 软件回声消除（speexdsp）；通话音量限幅；效果不佳则降级为"仅来电铃声 + 手机端通话" |
